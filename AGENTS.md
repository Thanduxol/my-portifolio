# AGENTS.md

## Project overview

A single-page developer portfolio built with TanStack Start (React 19) and Tailwind CSS v4. It renders one route (`/`) composed of stacked sections (hero, about, skills, experience, projects, certificates, learning, contact), each its own component under `src/components/portfolio/`.

## Architecture

- `src/routes/__root.tsx` — root document shell, page `<head>` metadata.
- `src/routes/index.tsx` — assembles the portfolio page from section components in order.
- `src/components/portfolio/*` — one component per section (`hero.tsx`, `about.tsx`, `skills.tsx`, `experience.tsx`, `projects.tsx`, `certificates.tsx`, `learning.tsx`, `contact.tsx`, `navbar.tsx`, `footer.tsx`), plus shared pieces (`section-heading.tsx`, `background-shapes.tsx`).
- `src/data/portfolio.ts` — the single source of truth for all editable content (personal info, skills, experience, projects, certificates, education, currently-learning items, nav links). Components import from here rather than hard-coding content, so new projects/certificates/skills only require editing this file.
- `src/components/ui/*` — small shadcn-style primitives (`card`, `badge`, etc.) generated by the template scaffold; kept for potential reuse, not all are used by the portfolio sections.
- `public/images`, `public/documents`, `public/certificates` — static assets (profile photo, CV PDF, certificate PDFs) referenced by path from `src/data/portfolio.ts`.
- `public/__forms.html` — a hidden static form skeleton required so Netlify's build bot can detect the contact form at build time (TanStack Start renders the real form client-side, which the build bot can't see). Do not remove; keep its field names in sync with `contact.tsx` if the form changes.

## Conventions

- All content edits should go through `src/data/portfolio.ts`, not inline into components.
- The site is single-theme (always dark) — theme tokens (maroon/green/charcoal/cream) are defined once in `src/styles.css` under `:root` and exposed to Tailwind via `@theme inline`. There is no light/dark toggle.
- Sections are identified by anchor IDs (`#home`, `#about`, etc.) matching `navLinks` in the data file — the sticky nav scrolls to these directly rather than using client-side routes.
- The contact form submits via `fetch` to `/__forms.html` (not `/`) because this is an SSR app — posting to `/` would hit the SSR handler instead of Netlify's form-processing middleware.

## Non-obvious decisions

- Content-collections (markdown-based content) from the original template was removed in favor of a single typed TypeScript data file — simpler for a non-technical owner to edit than markdown frontmatter, and avoids a build dependency for content that changes infrequently.
- The Download CV buttons link directly to the uploaded CV PDF (`public/documents/Thanduxolo-Tshiba-CV.pdf`) rather than generating a PDF dynamically from page content.
